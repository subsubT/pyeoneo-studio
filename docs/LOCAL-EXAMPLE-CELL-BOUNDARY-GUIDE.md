## 1. 문제와 목표

사용자가 제시한 출력:
- 실제 교육활동: 생활 속 다양한 자료를 표로 나타내어 정리하고 알게 된 사실과 나타내면 편리한 발표했다.
- 참고 예시문장: 생활 속 다양한 자료를 표로 나타내어 정리하고 알게 된 사실과 나타내면 편리한 발표함.

첨부 PDF의 실제 4쪽 평가 요소:
생활 속 다양한 자료를 표로 나타내어 정리하고 알게 된 사실과 표로 나타내면 편리한 점 발표하기

수정 목표 예문(실행 결과가 아님):
- 실제 교육활동: 생활 속 다양한 자료를 표로 나타내어 정리하고 알게 된 사실과 표로 나타내면 편리한 점을 발표했다.
- 참고 예시문장: 생활 속 다양한 자료를 표로 나타내어 정리하고 알게 된 사실과 표로 나타내면 편리한 점을 발표함.

두 번째 ‘표로’는 다른 절의 필수 내용이고 ‘점’은 ‘편리한’의 수식을 받는 명사다. 이를 중복 표현이나 군더더기로 삭제하면 안 된다. ‘점’만 임의로 끼워 넣는 완성 문장 치환으로 해결하지 않는다.

## 2. 확인한 원인과 근거 수준

### 2-1. 시작점은 표의 열 배정 오류다

lib/core.mjs의 parsePlanPages는 ‘성취기준’과 ‘단원명’ 제목의 x좌표 차이로 표 전체에 단일 배율·오프셋을 적용하고, 고정 배열 [161,215,266,333,498,706]으로 열 경계를 만든다. ‘평가영역’ 제목만 작은 허용 오차로 확인하므로, 앞부분이 유사하고 뒷부분 열 너비가 다른 표도 지원 양식으로 받아들일 수 있다.

첨부 PDF 4쪽을 직접 읽고 표 선·문자 좌표를 확인했다.
- 성취기준 제목 x=103.20, 단원명 제목 x=182.28.
- 코드의 scale=(182.28-103.20)/76.32, offset=103.20-97.68×scale.
- 계산되는 평가 요소/수업·평가 방법 경계: x≈347.03.
- PDF에 실제로 그려진 해당 세로 경계선: x≈377.35.
- ‘알게 된 사실과 표로’의 두 번째 ‘표로’ 시작: x≈351.48.
- ‘나타내면 편리한 점’의 ‘점’ 시작: x≈359.04.

즉, 정상적인 평가 요소 셀 안의 두 단어가 코드의 추정 경계 오른쪽에 있다. 현재 row.filter(t=>t.x>=b&&t.x<bounds[c+1])는 토큰 시작점만으로 열을 정하므로, 이 위치의 토큰은 평가 요소가 아닌 수업·평가 방법 열에 들어갈 수 있다. 원본에 없는 말이 필요한 상황이 아니라 원본에 있던 말의 잘못된 필드 배정이다.

근거 구분:
- 원본에 두 표현이 존재하고 실제 표 선/단어 좌표와 코드 계산 경계가 어긋난다는 점은 직접 확인했다.
- 사용자 출력의 누락 위치와 이 잘못된 경계가 일치한다.
- 좌표는 별도 PDF 판독으로 읽었다. 해당 사용자 세션의 PDF.js 토큰·저장 작업 JSON과 앱 실행 경로를 캡처해 재현한 것은 아니다. 최종 인계에서 이를 ‘실행 재현 PASS’로 바꾸지 않는다.
- PDF.js의 토큰 분할 방식에 따라 오배정 양상은 달라질 수 있으므로, 특정 두 단어의 좌표만 보정하는 방식으로 고치지 않는다.

### 2-2. 손상된 평가 요소가 두 예시로 함께 전파된다

app/components/activity-inputs.jsx의 ‘예시 만들기’는 createInputExamples(item)를 호출한다. lib/input-examples.mjs는 element를 먼저, method를 다음 원천으로 사용한다.
- 실제활동: flatDraft → actualSentence → result.
- 참고예시: 같은 선택 원천 → referenceSentence.
- 두 결과 모두 repairSentenceGrammar 등 공통 전처리를 거친다.

element에서 이미 말이 빠져 있어도 끝의 ‘발표하기’는 정상 서술어로 인식된다. actual은 과거형을, reference는 명사형을 붙여 같은 손상을 문체만 바꾸어 출력할 수 있다. 이 버튼의 예시는 로컬 규칙으로 만들어지므로, 이 문제를 AI 제공사·모델 품질·temperature 탓으로 단정하거나 프롬프트만 고쳐서는 안 된다.

### 2-3. 조사 보완과 완결성 판단도 부족하다

lib/reference-spacing.mjs의 OBJECT_NOUNS/isObjectNoun에는 이 문맥의 ‘점’이 없다. 원문을 온전히 추출해도 ‘편리한 점 발표하기’에서 목적격 조사가 보완되지 않을 수 있다. 다만 이 목록 누락은 단어 자체가 빠지는 원인은 아니다.

lib/sentence-style.mjs의 sentenceStyleIssues는 주로 명사형 종결을 검사한다. ‘편리한 발표함.’처럼 수식 대상이 사라진 문장도 끝이 ‘함.’이면 의미·호응 문제를 놓칠 수 있다. 종결어미 적합성과 원천 내용 보존·문장 완결성을 구분해 다뤄야 한다.

## 3. 수정 범위와 실행 순서

시작할 때 AGENTS.md → docs/STATUS.md → docs/PRODUCTION-OPERATIONS.md를 읽고 최신 개발 HEAD와 실제 운영 대상을 확인한다. 위 SHA로 강제 초기화하지 않는다. 별도 PDF 쪽수 제한 제거 가이드가 작성되어 있으나 이 가이드 작성 시점에는 구현 결과를 받지 않았다. 같은 작업에 임의로 합치거나 다른 작업을 되돌리지 않는다.

### A. 1단계의 열 경계 추정을 먼저 고친다

1. 앞의 두 제목으로 얻은 단일 배율을 모든 열에 그대로 적용하는 가정을 제거하거나 엄격한 지원 양식 판정 뒤에만 사용한다.
2. 실제 표 세로선/셀 경계와 각 제목의 위치·폭을 이용해 열마다 독립 경계를 구한다. 현재 PDF 읽기 경로에 표 선 정보가 없으면 lib/files.mjs에서 현재 PDF.js 버전이 제공하는 도형/변환 정보를 살펴 최소한의 페이지별 경계 메타데이터를 전달한다. 실제 좌표계·페이지 변환을 맞추고 내부 문서/설치본 API를 확인해 구현한다.
3. 표 선이 불완전한 양식은 여러 제목과 행별 텍스트 영역을 함께 이용하되, 제목 중심의 단순 중간값만으로 확정하지 않는다. 칸 너비가 제각각인 표와 제목이 분리 토큰인 경우도 고려한다.
4. 표 외곽, 평가 요소/방법, 평가 기준/단계 라벨/평가 시기까지 함께 분리한다. 특정 경계를 오른쪽으로 넓혀 방법 내용이나 옆 평가 기준까지 평가 요소에 섞는 수정은 금지한다.
5. 토큰 시작 x 하나만 보지 말고 폭·겹침과 셀 구조를 고려한다. 여러 셀을 가로지르는 토큰을 임의로 복제·잘라 붙이지 않는다. 실제 문자 위치를 알 수 있을 때만 그 근거로 나누며, 불명확하면 원문과 출처를 유지한 편집 가능한 검토 경로로 보낸다.
6. 새 추출의 내부 처리에서 원본 토큰이 어느 필드에 배정되었는지 추적할 수 있게 한다. 행 안의 토큰을 중복 배정하거나 조용히 버리지 않는다. 헤더/불릿/수준 라벨처럼 별도 취급한 토큰은 구별한다. 교육 원문·토큰 본문을 서버 로그에 남기지 않는다.
7. 근거가 부족한 표를 ‘추출 성공’으로 확정하지 않는다. 기존 원문 확인·직접 편집 흐름을 활용해 손실 없는 원문과 검토 필요 상태를 제공한다. 모든 PDF 업로드·짧은 입력·예시 생성을 새 일괄 차단하는 정책은 만들지 않는다.
8. 최근 lib/pdf-text.mjs의 셀 내부 줄바꿈·정상 어절 공백 복구는 유지한다. 열/행/단계 경계를 정한 다음 셀 내부 줄을 연결해야 하며, 다른 셀의 텍스트를 합쳐 문장을 매끄럽게 만드는 방식으로 감추지 않는다.

해당 원본의 평가 요소는 조사 보완 전까지 ‘…알게 된 사실과 표로 나타내면 편리한 점 발표하기’ 전체를 보존해야 한다. 반복된 ‘표로’도 각각 남긴다. 추출 단계는 원문 충실도 복구이며, 조사 삽입·동사 시제 변경은 생성 단계의 역할이다.

### B. 두 예시가 같은 온전한 과제 구조를 사용하게 한다

1. lib/input-examples.mjs와 lib/input-example-reference.mjs의 새 예시 처리에서 원천 과제, 절별 수행 동사, 목적어/수식부, 명시 조건과 원천 위치를 공유할 수 있도록 최소한의 공통 분석 결과를 마련한다. 무거운 범용 한국어 파서를 새로 도입할 필요는 없다.
2. actual/reference는 같은 원천의 핵심을 보존하고 렌더링만 나눈다. actual은 과거형, reference는 동사에 맞는 현재 ‘~ㅁ/음.’을 쓴다.
3. 이번 문장은 ‘자료를 표로 나타내어 정리함’과 ‘알게 된 사실 및 표로 나타내면 편리한 점을 발표함’의 두 수행을 모두 유지한다. 발표를 참여로 바꾸거나 수식절을 별도 수행으로 쪼개지 않는다.
4. PDF 줄바꿈·쉼표·와/과·및이 명사 나열/수식절 내부에 있으면 이를 독립 과제 경계로 오인하지 않는다. 미인식 부분을 삭제하고 마지막 동사만 그럴듯하게 활용하지 않는다.
5. 최소한의 내용 보존·완결성 판정을 종결형 판정과 분리한다. ‘…하면 편리한’처럼 뒤 명사·서술 관계가 부족한 부분, 목적어 나열의 한쪽 소실, 조건/부정/도움·수량 소실을 구조와 원천 구간에 비춰 다룬다. 모든 ‘한+동사’를 오류로 취급하는 정규식은 쓰지 않는다.
6. 이 판정은 제품 런타임의 새 예시 처리다. 이번 작업에서 테스트를 실행한다는 뜻이 아니다. 규칙만으로 불확실하면 기존 편집 가능한 원천 보존 초안을 사용하고, 같은 손상 문장에 ‘했다/함’만 붙여 자연스러운 완성문으로 내보내지 않는다.
7. 원천 단계에서 누락된 단어를 생성기가 무작정 추측해 채우지 않는다. 원본 셀에서 다시 확보하거나 검토용 원문을 제공한다. 정상 추출이 되었을 때는 이번 목표처럼 자연스러운 두 예시가 생성되도록 실제 경로를 수정해야 하며 경고 추가만으로 종료하지 않는다.

### C. 목적격과 수식 관계를 문맥에 맞게 보완한다

1. ‘표로 나타내면 편리한 점 발표하기’는 ‘표로 나타내면 편리한 점을 발표하기’로 준비한다. 받침에 맞는 accusativeParticle을 재사용한다.
2. 점/사실/이유 등 평가문에 자주 등장하는 명사 머리는 실제 목적어 역할과 인접 수행 동사를 보고 확장한다. 단순 목록 확장이 안전한 경우와 구조 판단이 필요한 경우를 나누되 이번 ‘점’은 처리한다.
3. ‘사실과 … 점’처럼 연결된 명사구에는 마지막 머리에 조사를 붙이고 ‘사실을과’처럼 중간 명사 뒤에 끼워 넣지 않는다.
4. 수치의 소수점·점수, 이미 조사가 있는 ‘점은/점에서/점을’, 인용·작품명·고유명 안의 ‘점’은 전역 치환하지 않는다.
5. 이미 자연스러운 문장에 반복 적용해 조사·마침표·내용이 중복되지 않게 구현한다. 모든 동사를 ‘함’으로 통일하지 않는다.

### D. 화면·복사·기존 데이터 연결을 보존한다

- 미리보기와 복사는 같은 pair.actual/pair.example을 사용한다. 화면만 보정하거나 복사할 때 원천에서 다르게 재생성하지 않는다.
- referenceSources와 수정 전 표시는 실제 선택한 원천을 유지한다. 잘못된 추출 결과를 고친 원본인 것처럼 표시하지 않는다.
- 이번 수정은 새 PDF 추출 및 새 예시에 적용한다. 기존 교사 입력·후보·승인·저장 작업을 열 때 자동 재작성하지 않는다. 기존 손상 항목은 새로 추출/검토한 뒤 예시를 다시 만들거나 교사가 수정하는 경로를 안내한다.
- AI 후보의 example 우선/공란이면 actual 계약, 원본별 정확 substring evidence/evidenceSource, 독립 검토·전체 확인·교사 최종 승인·승인 전용 출력은 유지한다. 참고 예시를 학생의 실제 수행 확정 근거로 바꾸지 않는다.
- 기존 무료 모델/키/활성 플래그/공유 한도/중지키, 정상 생성+검토 2호출·503 추가1회/최대3호출, PDF50MB·작업200MB 및 다른 기존 한도는 유지한다. 새 교정 API·유료 서비스·추가 모델 호출을 도입하지 않는다.

## 4. 금지하는 임시 처방

- 위 완성 문장을 통째로 하드코딩하거나 해당 PDF·4쪽·좌표값만 예외 처리.
- ‘편리한’ 뒤에 항상 ‘점’을 삽입하거나 모든 반복 어구 삭제.
- 열을 무조건 넓히거나 옆 셀 문장을 합쳐 원문 손실을 은폐.
- AI 모델/프롬프트만 변경하고 로컬 추출·예시 경로는 방치.
- 어미 검사만 통과하면 정상 문장으로 간주.
