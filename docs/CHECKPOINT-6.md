# Checkpoint 6: 평가계획 PDF 추출·편집·선택

상태: 완료 / 2026-10-28. 공개 배포 없음.

## 변경

작업 흐름을 두 단계로 분리했다.

1. 평가계획 PDF 업로드 → 교과별 전체 목록 검토 → 항목/교과 선택·해제 → 계획 수정/누락 추가 → 원본 대조 → 선택한 계획 확정.
2. 선택 항목별 실제 활동·예시 입력 및 사실 확인 → 문장 생성 또는 직접 후보 작성 → 검토·승인 → 교과별 조합·XLSX.

첫 단계는 교과별 표에 모든 항목을 표시한다. 선택 해제한 행도 남고 언제든 재선택할 수 있다. 교과·단원·영역·성취기준·평가 요소·방법·네 수준 기준을 편집한다. 분류하지 못한 기준 원문은 그대로 노출하고 빈 수준을 자동 보완하지 않는다. 교과와 평가 요소가 없는 선택 항목 또는 선택 0개는 확정하지 않는다. 나머지 빈칸은 교사가 원본으로 확인하며 자동 생성하지 않는다.

원본 PDF를 브라우저 canvas로 해당 쪽에 렌더링한다. 확대 보기와 추출 원문을 제공하며, 항목마다 sourceId와 쪽수를 연결한다. 여러 PDF를 추가해도 출처를 분리한다. 누락 항목에 원본 PDF/쪽수를 직접 연결할 수 있다. 지원하지 않는 서식은 전체 추출 원문을 보고 직접 추가한다. 기존 `parsePlanPages` 추출 방식은 그대로 재사용한다.

계획 편집·선택 변경·항목 추가·PDF 추가 후에는 확정을 해제한다. 확정 전 문장 단계는 잠긴다. 문장 화면, 승인 집계, 조합과 XLSX에는 선택한 항목만 전달한다. 선택 해제 자체는 사실·후보·승인 문장을 바꾸지 않는다. 계획 내용을 수정하면 해당 항목의 기존 승인은 후보로 보관하여 재검토한다.

## 작업 파일

- v2 JSON: 편집한 전체 항목, included, planConfirmed, 원본 PDF bytes(base64), 파일명, 페이지별 추출 원문, sourceId/page, 원본 XLSX 예시, 문장, 현재 항목과 조합 순서를 포함.
- 최대 40MB, 100항목, PDF 10개, 예시 2,000개. PDF 업로드 자체는 기존과 동일하게 10MB/30쪽 이하. 한도 초과 시 기존 상태를 바꾸지 않는다.
- 현재 작업에 추가로 불러온다. PDF/항목 ID를 새로 발급해 동일 파일을 반복해서 열어도 출처 충돌을 막는다. 기존 작업과 합치면 계획을 재확정해야 한다. 빈 작업에 열면 저장한 계획 확정/선택 상태를 복원한다.
- v1 하위 호환. 과거 파일에 없던 원본 PDF는 만들어 내지 않고 없음을 표시한다. 남아 있는 쪽수는 보존한다.
- 복원된 승인 문장은 후보에 보관한다. 실제 활동 확인과 교사 재승인이 필요하다. 승인/후보 합계 최대 240개를 반복 저장·복원해도 임의로 자르지 않는다.
- 작업 JSON은 원본 교육 자료를 포함하므로 Git에 넣지 않는다. 실제 검증 산출물은 ignored `tmp/checkpoint6/`에만 보관.

## 검증

- 네트워크 없는 기존 24개 + 계획 회귀 12개 = 36/36 PASS.
- 실제 참고 PDF 9쪽에서 기존과 같은 16항목(국어 4/수학 5/바른생활 3/슬기로운생활 2/즐거운생활 2) 추출 PASS.
- production build PASS. 제한 실행의 `.next` mkdir EPERM 후 일반 실행에서 통과. OS/기관 보안 설정 변경 없음.
- 로컬 production 브라우저 전체 흐름 PASS: 실제 PDF 16항목 전체 선택/교과 전체 해제/개별 해제·재선택, 교과·단원·성취기준·평가 요소·방법·4수준 편집, 누락 1항목 추가 후 제외. 17개 중 선택한 2개만 문장 단계에 표시.
- 원본 9쪽 PDF bytes가 작업 파일의 base64를 복호화한 bytes와 완전히 일치. 추출 원문은 계획 편집 후에도 동일. 원본 canvas와 쪽수 대조 화면 시각 확인.
- 미확정/확정 작업 저장·복원, 15개 제외 상태 보존, 선택 2개 보존, 문장 2개 보존 및 복원 시 재승인 필요 PASS. 0개 선택 및 이름 없는 선택 항목의 확정 차단 PASS.
- 기존 XLSX 원본 예시 168개 읽기, 실제 활동 빈칸 시작, 사실 확인 전 후보 추가 차단, 교사 검토 전 승인 차단, 직접 작성 문장 2개 승인 PASS.
- 승인 항목 제외 후 나머지 항목만 XLSX 출력, 재선택 시 승인 유지, 같은 교과 두 항목 조합 및 XLSX 재열기 PASS. 선택 2개/제외 15개 상태로 최종 작업 저장 PASS.
- 390px 모바일 root 가로 넘침 없음. 데스크톱/모바일/원본 대조 캡처 시각 확인. 콘솔 오류 0 / 경고 0.
- 로컬 production API GET enabled=false / POST 503. UI의 AI 생성 요청 0회. 기존 공개 API GET도 HTTP 200 / enabled=false 확인.
- 브라우저 근거: ignored `tmp/checkpoint6/browser-result.json`, `pdf-compare.png`, `plan-desktop.png`, `plan-mobile.png`, 작업 JSON 4개, 다운로드 XLSX 2개. 검증 스크립트는 저장소에 포함하고 원본 자료/작업 파일은 제외.
- 첫 개발 실행의 PDF 모듈 오류와 테스트 필드 이름 오류를 성공 결과로 간주하지 않았다. 깨끗한 개발 모드에서도 오류 스택을 재확인했다. 동일 버전 PDF.js의 공식 `build/pdf.min.mjs` 엔트리로만 변경해 개발 모드 16항목 추출도 통과했다([동일 계열의 upstream 이슈](https://github.com/vercel/next.js/issues/89177)). 추출 알고리즘/라이브러리 버전은 그대로다. 동적 입력란의 접근성 이름을 명시했다. 파비콘 404는 앱 아이콘을 추가해 수정했다.
- 비밀값 패턴 검사 PASS. `.env.local` 원본 일치, Git 제외, 클라이언트 및 이번 작업 파일·캡처를 포함한 파일의 실제 키/토큰 누출 0건.

재현: `npm test`, `npm run build`, `npm start -- --port 3006`. 브라우저 검사는 Playwright 설치 환경에서 `PLAYWRIGHT_MODULE`(필요 시 모듈 절대 경로)을 지정해 `node scripts/checkpoint6-browser.mjs "평가계획 PDF 경로" "참고 예시 XLSX 경로"` 실행. 기본 설치된 Chrome 사용, `BROWSER_CHANNEL`로 변경 가능. 실제 자료 경로/내용은 저장소에 포함하지 않는다.

## 범위 유지

`lib/generation.mjs`, `lib/prompt.mjs`, `lib/server/*`, `/api/generate`의 모델·프롬프트·독립 의미 검증·후보 목표 12개는 변경하지 않았다. 이번 브라우저 시험은 AI 비활성 상태에서 직접 작성한 가상 문장으로 승인·XLSX 회귀를 검증하며, 실제 모델 품질 재검증을 뜻하지 않는다. Checkpoint 5 품질 동등성 미충족 상태는 [기존 기록](AI-LATENCY.md)에 유지한다.
