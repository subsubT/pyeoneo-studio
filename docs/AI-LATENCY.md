# Checkpoint 5 후속: 로컬 응답 시간 비교

실제 시험: 2026-10-27 KST. 결과 정리: 2026-10-28 KST. **상태: 계측·오류 처리 및 미완료 시험 재실행 완료 / 품질 동등성 완료 조건 미충족.**

## 범위와 측정 방법

가상 색 탐색·낱말 읽기·수 비교·교사 도움 사례 4개로 기준 성능을 측정했다. 최종 채택안은 Checkpoint 5에서 미완료였던 동일한 낱말 사례와 부적합 5개/적합 대조군 1개로 비교한다. 실제 학생 자료는 사용하지 않는다. 모델은 `deepseek-ai/deepseek-v4.1-flash`, temperature 0.2, top_p 0.9, thinking=false 설정을 유지한다. 공개 서비스 재배포와 Vercel 환경변수 변경은 하지 않는다.

기준 코드는 `f83583ea5ccd86fa9f0af8f2b5bde60f2f97c35b`. `node scripts/ai-speed-benchmark.mjs baseline`은 해당 Git 버전의 모듈을 Git 제외 `tmp/speed-baseline/`에 복원해 실행한다. 최종안은 `node scripts/ai-speed-benchmark.mjs optimized --case=words --label=conservative-words`와 `node scripts/ai-speed-benchmark.mjs optimized --case=negative --label=conservative-negative`로 순차 실행한다. `.env.local`을 읽으며 키를 출력하지 않는다. 실제 외부 호출을 하는 명시적 시험이며 `npm test`에는 포함하지 않는다.

전체 시간은 생성→기계 검사→독립 의미 검토→응답 구성의 실제 경과 시간이다. 외부 시간은 NVIDIA HTTP 요청·응답 수신 구간이며 네트워크 왕복도 포함한다. 내부 시간은 전체에서 외부를 뺀 값으로 시험 기록 파일 쓰기도 포함한다. NVIDIA 내부 대기열·추론·네트워크 지연을 각각 분리할 서버 지표는 제공되지 않으므로 첫 응답 대기를 순수 추론 시간이라고 해석하지 않는다. Next.js 최초 컴파일·브라우저 렌더링은 이 CLI 비교에 포함하지 않는다.

스트림의 headersMs, firstByteMs, firstContentMs, bodyCompleteMs를 별도로 측정한다. 토큰은 서비스가 반환한 usage만 사용한다. 시간 초과 등 usage 미수신은 0토큰이라는 뜻이 아니다. 기준/개선 시험은 일부 시간대에 겹쳤고 각각의 사례당 단일 실행이다. 서비스 부하 변동의 영향을 받으므로 속도 차이를 모두 코드 변경의 인과 효과라고 주장하지 않는다.

## 구현

- 생성 1회 + 독립 의미 검토 1회 구조와 후보 목표 12개를 유지한다. 규칙 위반 후보는 기존처럼 표시하고 의미 검토 통과로 간주하지 않는다.
- 생성·독립 의미 검토의 프롬프트와 입출력 형식은 기준 코드와 동일하게 유지했다. 근거를 공통 목록으로 압축하고 프롬프트를 줄이는 실험은 출력 토큰을 줄였지만 품질이 낮아져 최종 코드에서 제외했다.
- 초기 실험(검토 근거 생략/종결 예시 축소)은 색 7/12 통과, 근거 복원 실험은 9/12 통과였다. 성취 보존 지침까지 추가한 실험은 색 11/12, 낱말 3/12였다. 특히 낱말은 기존 5/12보다 중복·종결 오류가 늘어 이 변경도 모두 되돌렸다. 기록은 Git 제외 `tmp/ai-speed/experiment-compact-review.json`, `final.json`, `final-quality.json`에 보존하며 채택안과 구분한다. 단일 실행만으로 변경과 품질 차이의 인과관계를 확정할 수 없어 보수적으로 제외했다.
- 생성 상한은 입력 길이에 따라 2,400~6,000토큰, 의미 검토는 2,400토큰이다. 상한에 도달한 응답은 실패 처리한다. 출력 상한 감소 자체가 실제 출력 토큰 감소나 속도 향상을 보장하지 않는다.
- 서버가 NVIDIA SSE를 수신하지만, 브라우저에는 완전한 JSON과 모든 의미 검토가 끝난 결과만 반환한다. SSE 종료 표식·finish_reason·응답 바이트 제한·JSON·검토 인덱스를 모두 확인한다. 모델 내용은 기존 256KiB 한도를 유지하며, 토큰마다 반복되는 SSE 메타데이터를 포함한 전송량은 별도로 4MiB까지 제한한다.
- 실패도 호출 시간·단계·오류 코드로 기록한다. 키·본문·학생 정보는 서버 로그에 쓰지 않는다. 타임아웃은 HTTP 504, 나머지 외부 실패는 502. 자동 재시도는 하지 않는다.
- 호출별 180초 한도는 유지한다. 전체 서버 처리 한도 360초, 브라우저 370초를 두고 연결 취소 신호를 외부 요청에 전달한다. 시간 제한을 짧게 잘라 측정상 속도를 높이는 방식은 쓰지 않는다.
- local opt-in, development, VERCEL 없음, Host/Origin 검사, 시간당 12배치, 동시 1배치 제한을 보존한다. 교사 승인·문장 규칙·XLSX는 유지한다.
- GitHub 저장 시 자동 배포를 막기 위해 `vercel.json`에서 현재 로컬 시험 브랜치 `checkpoint-5-local-ai`만 `git.deploymentEnabled:false`로 설정한다. [Vercel 공식 브랜치별 설정](https://vercel.com/docs/project-configuration/git-configuration)에 따른다. production 브랜치로 병합하거나 배포 명령을 실행하지 않는다.

## 결과

| 같은 가상 낱말 사례 | 기준 | 최종 로컬 구현 |
|---|---:|---:|
| 생성 | 143.101초 | 134.649초 |
| 독립 의미 검토 | 149.320초 | 95.475초 |
| 전체 | 292.459초 | 230.172초 |
| 외부 API 호출 합계 | 292.421초 | 230.124초 |
| 앱/시험 기록 내부 처리 | 0.038초 | 0.048초 |
| 생성 입력 / 출력 토큰 | 786 / 795 | 786 / 796 |

전체 시간은 이 한 쌍에서 21.3% 감소했으나, 토큰은 1.3% 증가했다. 최종 구현의 첫 내용 수신 대기는 생성 124.230초, 검토 93.510초로 합계 217.740초였다. 전체의 94.6%가 첫 내용 수신 전 외부 대기이고, 외부 호출 전체는 99.98%다. 앱 내부 지연을 줄여 수십~수백 초를 해결할 상황은 아니다. 서비스 부하·네트워크·모델 출력 변동을 분리할 반복 표본이 부족하므로 이 21.3%를 보장된 최적화 효과로 해석하지 않는다.

낱말은 원래 프롬프트·형식으로 돌린 뒤에도 종결 오류 6개(그중 중복 1개), 의미 거부 3개가 있었다. 최종 통과는 3개다. 특히 ‘참여하여 수행함’에 대한 과도한 거부도 관찰되어 검토 일관성의 한계가 남았다. 생성·검토 규칙을 약화하거나 탈락 후보를 자동 승인하지 않았다. **‘문장 품질 및 검증 정확도 저하 없음’은 이 표본으로 입증하지 못했으므로 전체 작업을 완료로 판정하지 않는다.** 현재 코드는 로컬 시험용이며 안정적인 품질·속도를 확보한 버전이라는 뜻이 아니다.

Checkpoint 5 미완료 시험은 최신 코드로 실제 재실행했다. 낱말 생성·검토가 시간 초과 없이 완료되었고, 부적합 5개는 모두 거부, 적합 대조군 1개는 통과했다. 이 고정 대조 시험은 기준·최종 모두 6/6 정답이며, 139.931→94.476초, 입력 741→741 / 출력 280→205토큰이었다. 낱말 품질 동등성 미달과 고정 대조 시험 성공을 구분한다.

기준 4사례 전체는 색 263.664초(12/12 통과), 낱말 292.459초(5/12), 수 비교 263.661초(10/12), 도움 244.991초(4/12). 모든 생성 후보 수는 12개다. 채택하지 않은 압축 실험의 유리한 토큰 수를 최종안의 절감량으로 사용하지 않는다. [수치 원본 요약](ai-speed-measurements.json)에 단계별 지표를 저장했다.

남은 검증은 같은 고정 후보에 대한 반복 의미 검토와 여러 번의 동일 조건 교차 시험이다. 표본과 사전 품질 기준을 정한 뒤 확인해야 하며, 통과할 때까지 유리한 호출만 골라 비교하지 않는다.
