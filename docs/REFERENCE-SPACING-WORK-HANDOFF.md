## 과거 근거와 이번 미실행

Work가 기존 코드에서 합성 element/method로 오류를 재현한 것은 사용자 검증 생략 결정 이전의 과거 근거다. 실제 교사의 원본 필드/PDF 재현이 아니며 이번 Codex는 해당 재현 함수를 실행하지 않았다. `lib/core.mjs`의 PDF `parsePlanPages/join`이 행 이동/토큰 간격으로 공백을 넣는 경로임은 소스로 읽었지만, 이번 사례의 최초 유입 지점이 PDF라고 확정하지 않는다. 파서를 교체하거나 원문을 일괄 교정하지 않는다.

자동 테스트·회귀·정적/비밀값/도름스 검사·`git diff --check`·재현/비교표 생성·브라우저/PC/390px·API 요청 시험·실모델·로컬/별도 검증용 빌드를 실행하지 않는다. 새 검증 스크립트·검증 산출물도 만들지 않는다. 제품 문장을 실행하여 필수 목표/정상 표현/멱등성/원문 보존을 확인한 것으로 보고하지 않는다. 사용자가 배포 후 공백·복사/수정·저장/복원을 직접 확인한다.

Git 상태/커밋/원격 및 배포 소스·팀/프로젝트/도메인 metadata 조회와 업로드용 digest 계산은 정확한 소스 배포를 위한 운영 처리다. 제품 검증과 구분한다. 배포용 payload는 Git 제외 `tmp/`에만 보관하고 Git 커밋의 추적 파일만 업로드한다. 비밀값/교육자료/환경 파일을 새로 추가하지 않는다.

## 배포 및 최종 인계

기존 MCP `upload_file` SHA1 참조 / `create_deployment(files=…, target=production)` 경로를 사용한다. 기존 플랫폼 빌드와 강제 처리는 수행하고 결과를 기록한다. 검증 생략을 이유로 보호 설정/CI/hook을 해제하거나 필수 플랫폼 처리를 우회하지 않는다. 사용자 실사용 확인을 기다리며 배포를 멈추지 않는다.

배포 전 기록 상태: 구현 완료, 커밋·push·배포 진행 예정. 정확한 개발/배포 SHA·ID·플랫폼 결과·미해결/복구 여부는 후속 문서 전용 커밋으로 확정한다. 최종 문서 SHA는 이 파일의 마지막 변경 커밋이며 최종 대화에도 명시한다. 문서 마무리만으로 앱을 재배포하지 않는다.
