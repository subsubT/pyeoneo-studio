## 채택한 생성 방식과 상태 경로

`lib/input-examples.mjs`의 로컬 규칙으로 확정한 평가 요소의 활동을 문장화한다. 평가 요소가 구체적인 활동으로 해석되지 않으면 같은 항목의 수업·평가 방법을 살펴본다. 공통 활동 어미·연결 표현·일부 생략된 목적격 조사를 처리하며, 한 활동 문구에서 활동 예시와 참고 예시문장을 함께 만든다. 활동·조건·도움을 유지하고 참고 문장에는 기존 `validateText`의 금지 어휘·길이·‘함.’ 종결 검사를 적용한다. 수준별 기준·기존 승인·참고 예시에서 미확인 성취를 보태지 않는다.

외부 요청·키·새 패키지·후보 12개 생성 재사용 없음. 같은 항목에서 다시 만들면 같은 예시가 나오는 결정적 규칙이다. 구체적인 활동이 없거나 지원하지 않는 표현, 길이·금지 어휘 문제가 있으면 구체화 안내를 표시한다. 임의의 동일 고정 활동을 넣지 않는다. 이는 모든 자유 문장의 한국어 문법·의미를 해석하는 모델이 아니므로 교사가 확인해야 하며, 직접 입력은 항상 가능하다.

`app/components/activity-inputs.jsx`는 예시를 입력창 옆에 별도로 표시한다. 각 ‘복사’는 클립보드 붙여넣기 없이 해당 칸의 전문을 즉시 교체한다. 해당 칸에 다른 글이 있으면 `window.confirm`으로 교체 여부를 확인한다. 취소하면 양쪽 입력·사실 확인 상태를 보존한다. 예시 생성·재생성은 입력·사실 확인·후보·승인을 갱신하지 않는다. 항목 ID를 React key로 사용하므로 항목 전환·계획 편집 시 미리보기를 초기화한다.

직접 입력과 복사 모두 `Home.update` → `editItem` → 같은 항목의 `actual` 또는 `example`로 갱신된다. 내용이 바뀌면 기존처럼 사실 확인을 해제하고 승인 문장을 후보로 보관한다. 필수 입력의 기존 길이 조건(활동 8자·참고 문장 5자)을 유지했다.

- 후보 생성: `Home.generate`가 현재 항목의 최종 `actual`·`example`을 snapshot으로 잡아 `/api/generate` POST body에 사용한다. 생성 중 입력 변경에 대한 기존 응답 반영 조건도 유지했다.
- 저장: `saveWork` → `serializeProject({items, ...})`가 같은 최종 상태를 저장한다.
- 복원: `restoreProject`가 입력값을 보존하고 사실 확인·문장 승인은 다시 요구한다.
- 예시 미리보기는 저장하지 않는다. 복사하거나 직접 수정한 입력값은 작업 파일에 보존한다.
